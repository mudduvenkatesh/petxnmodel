Market Data & Override — Data Model & Flow

How Client Master (Semarchy) and Salesforce work together to show market-sourced values, let relationship managers override them with a reason, keep a full decision history, and feed those decisions back to improve source quality.

The concept

Two systems, one clean split — plus a running history

Semarchy owns what the market says. Salesforce owns what we display and what we decided. Neither silently overwrites the other, and every decision is logged.

1

Contact (effective value)

Standard Salesforce fields (Name, Email, Phone, Address…) hold the value everyone sees and every integration reads. Nothing else in Salesforce has to change.

2

Market Data Control Table

A child record per field carries the market value, its sources & as-of date, the field state, and the override decision + reason. This is what the field component reads and the Data Review page manages.

3

Market Data Audit

A running, append-only history of every decision — override, accept market, keep, or match event — with who, when, the change, and the reason. Powers the Audit tab.

Ownership

Who is the source of truth for what
Client Master · Semarchy

Master of market data & distributor of the golden record

  • The market value for each profile field
  • Market Profile Metadata — one JSON object per field: which sources provided the value and the most recent date one did
  • Publishes updates to Salesforce; never writes the displayed value directly
  • Distributor of the Final Golden Record — takes the resolved values back from Salesforce (post any salesperson decisions) and distributes the golden profile across Apollo
⇄
Salesforce

Master of the effective value & decisions

  • The displayed value on the Contact
  • The override state, who/when, permanent flag, and reason
  • The decision history — and the feedback signal sent back to Semarchy

Field states

One field, one tag — driven by Value Source
MKT
Value Source = Market. The displayed value came straight from market data. Hover shows the source(s) and as-of date.
OVERRIDDEN
Value Source = Manual Override — no alert. A person is deliberately holding a value that differs from market, and the market data is not newer than that decision. Nothing to review right now.
OVERRIDDEN  
Value Source = Manual Override — active alert. Same as above, but newer market data has arrived (As-Of > Overridden On). The bell flags it for review in the field hover and on the Data Review page. “Keep permanently” locks it instead (next state).
OVERRIDDEN  ∞
Value Source = Manual Override — permanent. The user chose “Keep permanently,” locking the override (Override Locked). The ∞ replaces the bell and no future market update will flag it for review.
NO MKT DATA
Value Source = No Market Data. A person entered a value for a field no source provides. Nothing to override; shown for transparency.

Data flow

How an initial push proliferates through Salesforce

When Semarchy publishes, the data fans out across the Salesforce tables in a set order: the control table is written first, then the Contact fields and the audit rows are derived from it.

1 · Semarchy publishes
  • Market value for each field
  • Market Profile Metadata (sources, as-of)
→publish
2 · Market Data Control Table
  • Upsert one row per field
  • Value · Sources · As-Of · Metadata
  • Contact not touched yet
→resolve
3 · Contact fields + Value Source
  • Fill market value where the field is empty
  • Keep existing values → decide Market vs. Override
  • Set the bell where market is newer
→log
4 · Market Data Audit
  • One initial entry per field
  • Filled / Adopted / Preserved / No Market Source

Two entry scenarios
Scenario ANew record from Semarchy
  1. Create the Contact from the incoming Semarchy record.
  2. Upsert one control-table row per market field (value, sources, as-of, metadata).
  3. Every Contact field is empty, so copy the market value into each field. Value Source = MKT across the board.
  4. Audit: one “Filled from Market” entry per field.
Result: a fully market-sourced contact — every market-backed field shows MKT, and no overrides exist yet.
Scenario BExisting Salesforce record matched for the first time
  1. Upsert one control-table row per market field — the Contact fields are not touched yet.
  2. Resolve each field against the existing value (per the rules above): fill blanks from market; keep values that already equal market; preserve differing manual values as OVERRIDDEN; adopt market on system-authoritative fields (e.g., Name, Dual Registered, CRD).
  3. Set the bell wherever the market As-Of is newer than the preserved value.
  4. Audit: one entry per field — Filled from Market / Adopted on Match / Preserved on Match / No Market Source.
Result: manual values are preserved (never silently overwritten), blanks are filled from market, and system fields adopt market — exactly the “post-match” state in the prototype.
↩
Feedback loop. Override decisions and their reasons flow back to Semarchy so stewardship can see where and why values diverge from market — the signal that continuously improves source quality.

Match behavior

When a manually-created contact matches market data

Manually-entered values are never silently overwritten. On match, each field resolves by its configured policy (owned by the Salesforce team):

Field policyIf a manual value existsResult
Preserve as overrideyesKeep the manual value; state = OVERRIDDEN — even if identical to market (no silent override). Logged as “Preserved on Match.”
Adopt marketyes / noTake the market value; state = MKT. Logged as “Adopted on Match.” (e.g., Name, Dual Registered, CRD.)
anyno manual valueTake the market value; state = MKT.
any (no market ever)manual valuestate = NO MKT DATA.
